# Stoke v0.2.3

Security-release candidate integrating the reviewed request-policy remediations with the current public gateway and website changes.

## Security and compatibility

- Operator dashboard access requires the separate `STOKE_ADMIN_KEY`; inference credentials remain scoped to client operations and their own budget view.
- Nonzero route budget/rate settings now fail startup with migration guidance to `[[keys]]`.
- Explicit model prices apply to local and remote tiers as well as cloud providers; unpriced owned-machine inference remains unmetered.
- Finite-budget requests are fail-closed: unsupported fan-out, unbounded content, invalid token limits, and native-hook paths are refused before provider dispatch.
- Durable budget reservations are request-owned and settle or cancel atomically; uncertain provider usage retains a conservative hold rather than silently charging zero.
- PII redaction covers structured content and JSON-encoded tool/function arguments while preserving roles, identifiers, schemas, and URLs as metadata.
- Webhook and JavaScript policy failures fail closed; configured empty or invalid JavaScript plugin paths are startup errors, and plugin chains retain prior policy context. Mandatory output webhooks use the hardened, redirect-disabled, proxy-disabled and DNS-pinned transport with a 1 MiB response limit.
- Absent or identity JavaScript output hooks preserve the original successful response. The Messages bridge explicitly refuses unsupported interleaved Chat tool-call fragments rather than assigning arguments to a different tool.
- Response cache entries retain caller/route/request identity and remain bounded by entry count, serialized bytes, and TTL. Named-route exact caching and bounded coalescing remain opt-in.
- Valid, unambiguous upstream retry hints remain preserved without widening the retry policy.
- OpenAI Responses and Anthropic/native bridge paths keep their existing credential, subscription, streaming, routing, and header compatibility contracts while applying the new admission and settlement checks.

## Scope and limits

This candidate changes the public gateway release path only. Private Cloud work and running services are unchanged. It does not provide provider credentials, local models, subscription entitlements, signing/notarization, or a claim of real-provider testing. Default builds do not include the optional V8/JavaScript feature; enable it explicitly with `--features js-plugins`.

The release workflow and public website remain part of the candidate. Publication still requires the independent CI, archive, checksum, and release-inventory gates to pass; preparing this worktree is not publication.

## Verification target

The deterministic local verification command is:

```sh
cargo test --locked
```

Native JavaScript tests and the security wire harness are separate feature-gated checks. Provider-backed behavior is not implied by offline execution.
