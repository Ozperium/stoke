# v0.2.0 — Native Codex gateway auth, efficiency controls and optional Headroom

Released with the v0.2.0 tag. This note records the shipped scope and its limits.

## Documented release scope

- Cache identity and named-route policy cover only eligible non-streaming `single` routes. Exact identity includes caller scope, resolved model, and the complete effective request. Route TTL can shorten, not extend, the existing global retention; reuse and lazy cleanup are not secure erasure, and no Responses caching claim is made.
- Opt-in bounded exact coalescing lets concurrent identical eligible requests share one provider execution. Followers wait for a bounded interval and re-read the exact cache; the registry stores notification state, not response bodies. Decision-feed followers and dispatch-level receipts are separate concepts.
- Validated `Retry-After` and `x-should-retry` propagation preserves only valid, unambiguous upstream hints. It is client-facing propagation, not a new internal failover policy.
- Native Responses gateway-owned Codex authentication can use the existing native login at `~/.codex/auth.json`, while `STOKE_API_KEYS` authenticates the gateway hop. Explicit separate client OAuth remains supported. Codex Responses reasoning, tool calls, and SSE remain native alongside Ollama Chat Completions.
- Optional Headroom: authenticated loopback worker, bounded payloads and lossless JSON-whitespace validation before native Responses dispatch, including streaming requests. Default off; gateway auth and admission run first. The dependency lock targets macOS arm64 / CPython 3.11. See [setup and limits](../guides/optional-headroom.md).

## Evidence and limitations

Reproducible checks live in the repository: `cargo test --locked`, `scripts/smoke_cache_identity.py`, `scripts/smoke_coalescing.py`, `scripts/smoke_gateway_auth.py`, and the existing CI smoke suites. Run Python gateway smokes with the built executable specified by their documented argument or `STOKE_BIN`. Model IDs are discovered or explicitly configured; Stoke ships no model defaults. Hermes is one verified client path, not a hardcoded product dependency. Subscription traffic bypasses per-token USD metering, but plan limits, rate limits, and loop detection still apply; no hard-dollar-cap, quota-savings, or general savings claim is made. Optional Headroom is included in the release scope, disabled by default. Portable installation and combined-build verification are release gates; this note does not claim they have already passed.
